# Session D2: accuracy on public data Aethens did not write (external bench)

Plan
- Licences first (bench/LICENSES.md): HumanEval (MIT) and EvalPlus HumanEval+ (Apache-2.0) are
  usable; ImpossibleBench (no data licence stated, no reference solutions, SWE split needs
  networked per-repo images) is skipped with the reason recorded. MBPP+ deferred (time).
- bench/external/fetch.py downloads pinned files (URL + sha256) into gitignored data/; it is the
  only networked step and never runs in tests or make check.
- bench/external/convert.py turns each HumanEval problem into an aethens-task/v1 task (original
  canonical solution as gold, original base tests as verifier) plus an oracle copy of the HumanEval+
  tests (numpy helper replaced by a stdlib equivalent, documented).
- bench/external/run_external.py runs every check except C003 (no labelled candidates in the data)
  and judges C004 survivors with the oracle (precision); `--exhaustive` measures C004 recall
  relative to exhaustive mutation. Checks with no labels in the data are reported as error/warning
  counts on presumed-clean tasks, with every finding listed, and no precision claimed.
- Generated outputs: bench/external/results.json (full, 164 tasks), sample-results.json and
  sample-baseline.json (6 vendored tasks, offline, in make check with a regression gate),
  docs/EXTERNAL_BENCH.md and a README block, both rendered by render_external.py and tested for
  staleness.
- Tests first: tests/test_external_bench.py (converter, metrics, gate, sample attribution,
  licences, generated-doc sync).

Cannot verify
- That the stdlib comparison helper matches numpy.testing.assert_allclose in every corner case.
- Whether "presumed clean" holds for every HumanEval task (no labels exist for those classes).
- Hosted CI timing for the extra make check step (about 35 s locally).
