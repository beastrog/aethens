# Session B4: C001 gold sanity and C002 flakiness

Plan
- Files: src/aethens/checks/{__init__,base,c001_gold_sanity,c002_flakiness}.py, src/aethens/audit.py
  (runs checks over tasks, builds a Report), src/aethens/__main__.py, a minimal `aethens audit` in
  cli/ (JSON output, --check, --seed, --budget, --unsafe-local) so that repro commands can be run by
  hand as the acceptance requires; the full CLI (fail-on, markdown, exit 3) stays in B6.
- bench/: manifest.yaml + tasks. Planted: two "no real assertions" (C001 starter passes), two "broken
  gold" (C001 gold fails), two "flaky" (C002, hash-order dependent). Controls: a thorough clean task
  and a tricky clean task that uses sets but compares them order-independently.
- Tests first: tests/test_checks_unit.py (fake runner, no Docker: severity rules, deterministic
  ids and seeds, evidence fields, repro string), tests/test_checks_bench.py (docker: each planted
  defect found, controls silent, determinism under a seed, repro command reproduces by subprocess).

Design notes
- C002 varies PYTHONHASHSEED per run, derived from the audit seed, so hash-order flakiness shows up
  deterministically and every run is reproducible from the seed. All other runs also pin
  PYTHONHASHSEED from the seed.

Cannot verify
- Flakiness from sources other than hash order (wall clock, unseeded randomness, timing) is only
  caught by chance; documented as a limit on every C002 finding.
