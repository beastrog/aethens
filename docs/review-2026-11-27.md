# Hardening review, 2026-11-27

Prompt 3 of docs/BUILD_PROMPTS.md. Caveat: this review was run by the same build agent that wrote
most of the code, in a session that had only the repo files as memory, not by a truly independent
reviewer. An independent read is still recommended before launch.

Every finding below either has a failing-then-passing test (fixed) or evidence and a proposed fix
(open). Severity is about impact on users of the tool.

## Open (not fixed: need an owner decision or out of scope)

| # | severity | finding | evidence | proposed fix |
|---|---|---|---|---|
| O1 | high | writes to `/work` have no size limit. `/work` is a bind mount of a host temp directory, so a task can fill the host disk for as long as its timeout allows. The read-only rootfs and the `/tmp` tmpfs limit do not apply | a container wrote 200 MiB to `/work` without error; the same container got ENOSPC writing 300 MiB to `/tmp` (256 MiB tmpfs) | an isolation change, so it needs owner approval. Options: a size-limited tmpfs at `/work` filled by a tar stream at start; a loop-mounted or quota-limited work filesystem; or at least a host-side free-space check. SECURITY.md now documents this and tells users to point TMPDIR at a size-limited filesystem |
| O2 | medium | if Aethens is SIGKILLed or OOM-killed, a running container lives until its verifier exits (forever for a hung one) | follows from the design: the timeout is enforced from the host | an in-container time limit (needs a `timeout` binary or a tiny init in the image: an isolation/image decision), or reaping `aethens.run=1` containers older than the maximum timeout at startup. SECURITY.md documents the cleanup command |
| O3 | low | docker CLI exit code 125 (a daemon error after the container started) is treated as a verifier failure and could give a C001/C002 false positive | code reading of DockerRunner._execute; not reproduced | treat 125 with no verifier output as a runner error (needs a rule, since a verifier may exit 125 itself) |
| O4 | low | in `--unsafe-local` mode a child that calls `setsid()` escapes the process-group kill | code reading of runner/local.py | documented as unsafe mode. Could track children via a cgroup on Linux |
| O5 | low | the loader accepts `tests: .` (or starter/gold `.`), which copies the whole task directory, including `gold/` and `candidates/`, into every run, so a starter run can import gold files | code reading of `_rel_path` and `run_spec` | reject `.` for these fields, or reject overlapping directories (a schema decision) |
| O6 | medium | the C004 equivalence filter hides real weaknesses: 5 survivors that HumanEval+ rejects were filtered on the external bench, and 7 reported counterexamples lie outside the task's precondition | docs/EXTERNAL_BENCH.md, DECISIONS D-065 | precondition inference (docs/IDEAS.md); a CLI switch to turn the filter off |
| O7 | low | C002's time budget sums host wall time per run, so on a loaded host it makes fewer runs and states a weaker bound. The bound is reported honestly in coverage | `RunResult.duration_s` is wall time (D-064) | sum in-container time instead (a change to C002 semantics) |
| O8 | low | C006, C005 and the equivalence probe assume `python -m unittest`; other verifiers get an info "checked nothing" or an inconclusive probe | README limits | none needed for v0.1 |

## Honesty: claims not backed by a bench report or test

- README "Quickstart (about a minute)": measured at 17 s for examples/add-two at the standard budget
  on the build box. Plausible, but this is not tested.
- README bench paragraph said hosted CI "has not run yet". Corrected: the first hosted run's
  artifact matched bench/results.json.
- README "Tested on Linux with Docker Engine": true for the build box and GitHub's ubuntu-24.04
  runners (both workflows pass). Docker Desktop, rootless Docker and Podman are untested, as stated.
- docs/COMPETITIVE.md describes other tools from their READMEs. Under AGENTS.md rule 6 none of it
  may go into the README as a comparison until it is reproduced on the same inputs. It is not in
  the README now.
- docs/DECISIONS.md D-0xx entries that say "hosted CI has not run" are historical and stay as they
  are. docs/STATUS.md is updated.
